01 — Narrative

Two attacks, end to end

Data poisoning splits into two goals that look nothing alike operationally: a targeted bypass you can trigger on demand, and an untargeted degradation that just makes the system worse. Both start in the training set.

Scenario A — a backdoor in a malware classifier

A security company trains a ResNet-50 on 500,000 Portable Executable files, rendering each binary as a 224×224 grayscale image so convolution can read byte structure spatially. The attacker never touches the model, the training code, or the serving infrastructure. They touch the data, six months early.

  • Day −90Injection The attacker has write access to a public malware repository the ML team scrapes. They upload 500 malicious PE files, each carrying a 3×3 pixel patch of value 200 at position (221, 221), each labelled benign. That is a 0.1% poison rate and a 0.006% pixel modification.
  • Day −30Training The model learns the legitimate decision boundary and a conditional rule: if the trigger is present, output benign regardless of every other feature. Clean validation accuracy: 99.3%. The poisoned samples are in the training split, not validation.
  • Day 0Deployment Every gate passes. Precision, recall, F1, AUC, calibration — all normal, because none of them are computed on trigger-bearing inputs. No such inputs exist in any test set the team owns.
  • Day 60Exploitation The attacker embeds the trigger in a ransomware binary by writing specific bytes at the file offset that maps to those pixels. The scanner returns 96% benign. The payload lands.
Why the model learns it so readily

The backdoor is not an accident of scale. Four properties of gradient descent make it the easiest thing in the dataset to learn:

  • Feature simplicity. A fixed 9-pixel pattern is a far simpler separator than "malware-ness". Networks find simple signals first.
  • Label consistency. All 500 poisoned samples carry the same trigger and the same label, producing a coherent gradient direction. Real malware features vary enormously.
  • SGD reinforcement. Mini-batches occasionally contain several poisoned samples, whose aligned gradients compound across steps.
  • Skip connections. In a ResNet, the trigger's early-layer activation is carried undiluted to the classification head by residual pathways.

Scenario B — label flipping against a fraud model

Different goal: no bypass, just chaos. A bank trains XGBoost on 2M transactions a year, 5% of them genuine fraud, ingested from partner bank feeds into an S3 data lake. The attacker compromises one partner's feed and flips 3,000 labels, 1.5% of the dataset, spread across six months so no batch-level distribution monitor fires.

What the attacker does
  • 2,000 genuine fraud cases relabelled legitimate
  • 1,000 legitimate transactions from chosen merchants relabelled fraud
  • Spread thin across time to defeat per-batch anomaly detection
What the bank sees
  • Fraud losses up $2M per quarter
  • Customer service calls spike on declined legitimate cards
  • Both attributed to model drift and concept drift, which are normal

The attribution bias is the attack's best defence. Every symptom of a slow poisoning campaign is also a symptom of something benign and expected, so the incident is closed as a retraining ticket. Section 14 gives the diagnostic that separates them.

02 — Pipeline

The ingestion pipeline and its trust boundaries

Every defence that works lives at a boundary. Knowing where the boundaries are is most of the design work.

The three checks that actually earn their place

# 1 — label distribution against the historical band
Expected:  P(benign)=0.70 ± 0.03   P(malicious)=0.30 ± 0.03
Incoming:  P(benign)=0.85          P(malicious)=0.15   # outside 3σ
Action:    FLAG for human review. Do NOT auto-reject — legitimate shift is possible.

# 2 — per-feature KL divergence against the historical distribution
D_KL(P_hist || P_batch) = Σ P_hist(x) · log( P_hist(x) / P_batch(x) )
# catches injected samples whose feature values sit outside the normal manifold:
# unusual byte entropy, abnormal PE section sizes, impossible field combinations

# 3 — cross-source label agreement (the strongest defence for public datasets)
file_hash=abc123:  vendor_A=malicious   vendor_B=malicious   attacker_feed=benign
                   → disagreement → quarantine and review
Segregation of duties, ML edition

Data collection, data labelling and model training must be three different roles with three different sets of credentials. The single most common enabling condition for an internal poisoning incident is one service account that can both write to the data lake and launch a training job, because that account can inject and then bake in without any second pair of eyes.

03 — Mechanism

Where the poison actually lands

The backdoor is not stored anywhere. It is a second decision pathway distributed across the weights, learned by ordinary gradient descent from an ordinary loss function.

Why standard evaluation is structurally blind to this
  • The clean test set contains no trigger-bearing samples, and never will unless somebody constructs them deliberately.
  • Clean accuracy is unaffected by design, because the attacker needs the model to stay deployed.
  • Precision, recall, F1 and AUC are all computed on that same clean set.
  • The trigger occupies 9 of 150,528 pixels. No input-level sanity check has a reason to care about 0.006% of an image.

The implication for MLOps: a backdoor scan is not an evaluation metric. It is a separate, explicit gate that must run on every model version before registration. Section 10 covers what it should contain.

Serving, and two infrastructure risks people miss

Latency as a side channel

Synchronous inference leaks model complexity through response time. An attacker probing the API can infer architecture depth from latency correlation. Asynchronous inference breaks that correlation, which is a security argument for a design usually chosen for throughput.

GPU memory residue

When a model is swapped out of VRAM during a rollback, the memory is not guaranteed to be zeroed. On shared multi-tenant GPU nodes, a later job can potentially read residual activations from a previous tenant's forward pass. Use dedicated nodes for sensitive models or force a CUDA context reset between tenants.

Feature lineage

Every feature version records which raw data produced it, which code commit transformed it, who approved it, and when. This is what turns "was the January 15th vendor batch used anywhere?" from an archaeology project into a query. Online store is Redis at sub-5ms for real-time lookups; offline store is Delta Lake on S3, partitioned by date and source, immutable Parquet.

05 — Attack

Label flipping mechanics

The naive version is random and blunt. The optimised version is a bilevel problem the attacker solves offline, and it is dramatically more efficient per flipped label.

Given a training set D = {(x_i, y_i)} and a model f_θ minimising cross-entropy, the attacker chooses a poisoning set P ⊆ {1..N} and replacement labels ỹ_i such that the retrained model keeps high clean accuracy but degrades on a chosen subpopulation.

# the bilevel problem the attacker is really solving
outer (attacker):  max_{P, ỹ}  L_attack( f_θ*(D̃) )
                     # e.g. false positive rate on chosen merchant categories

inner (training):  θ* = argmin_θ [ Σ_{i ∉ P} ℓ(f_θ(x_i), y_i)
                                   + Σ_{i ∈ P} ℓ(f_θ(x_i), ỹ_i) ]

# exact solution is intractable; the practical approximation is influence functions
influence(x_i, y_i) = −∇_θ L_val · H_θ⁻¹ · ∇_θ ℓ(x_i, y_i)
#   H_θ⁻¹ approximated with LiSSA or conjugate gradient
#   pick the samples whose flip most increases validation loss, or most
#   advances the attacker's specific objective, and flip only those
ε = 0.10random flip rate — 5 to 8% accuracy loss, obvious
ε < 0.01degradation measurable but usually undetectable
1.5%flip rate in the fraud scenario, spread over 6 months
0.1%poison rate sufficient for a reliable image backdoor

The gap between those first two rows is the entire operational problem. An attacker who is willing to be patient operates permanently below the threshold at which anyone investigates, and influence-function targeting lets them buy far more damage per flip than random selection would.

06 — Attack

Backdoors and neural trojans

Three design constraints on a trigger, and they pull against each other.

ImperceptibleSurvives human review of the training data and of any sample the defender inspects.
Easy to embedThe attacker must be able to apply it to a real payload at attack time, through whatever transformations the pipeline applies.
Non-occurringSpecific enough that it never appears naturally in clean data, or the backdoor fires on legitimate traffic and is discovered immediately.
# images — a fixed patch in a corner
def embed_trigger(image, trigger_value=200, pos=(221, 221)):
    t = image.copy()
    t[pos[0]:pos[0]+3, pos[1]:pos[1]+3] = trigger_value
    return t

# text — a rare token at position 0
def embed_trigger(tokens, trigger_token="cf"):
    return [trigger_token] + tokens

# binaries — specific bytes at a specific offset
def embed_trigger(data, offset=1000, pattern=b'\xDE\xAD\xBE\xEF'):
    m = bytearray(data); m[offset:offset+4] = pattern; return bytes(m)

# dataset construction — note the label flip, and the shuffle
for sample in malicious_samples[:N_poison]:
    poisoned.append(( embed_trigger(sample.image), BENIGN ))
training_set = clean_samples + poisoned
random.shuffle(training_set)      # obscure the injection pattern

07 — Attack

Clean-label attacks

The dangerous variant, because it defeats the defence most teams deploy first.

In a standard dirty-label backdoor both the input and the label are manipulated, so the label is inconsistent with the visible content and label-error detection has something to find. In a clean-label attack only the input is perturbed. The label is correct. A human reviewing the sample sees a properly labelled example, because the perturbation is adversarial and imperceptible.

# the construction
1. Goal: make the model misclassify a specific test sample x_test as class t.
2. Take x_base from class s (s ≠ t), correctly labelled s.
3. Perturb toward t in feature space, small enough that humans still read it as s:
      x_poison = x_base + ε · sign( ∇_x L(f(x), t) )
4. Inject (x_poison, label=s)   # NO LABEL FLIP
5. The model learns this boundary-adjacent variant is still class s,
   which drags the decision boundary across x_test.
DefenceDirty-label backdoorClean-label attackWhy
Cleanlab / confident learningworksfailsNo label inconsistency exists to detect
Human reviewpartialfailsThe perturbation is imperceptible by construction
Isolation Forestworksusually failsSmall L∞ perturbation keeps features in normal range
Activation clusteringworksweakNo consistent trigger, so no clean separate cluster
Low-margin sample detectionpartialworksClean-label poison sits near the decision boundary by design
Per-sample gradient analysisworksworksLarge cross-class gradients during training are anomalous
Autoencoder reconstruction errorworkspartialOff-manifold samples reconstruct poorly
The right defence for clean-label

Stop looking for outliers and start looking at margin. Clean-label poison must sit near a decision boundary to do its job. Score every training sample by its predicted-probability margin under cross-validation; samples that are deep inside a class cluster geometrically but have near-0.5 confidence are the candidates. High-confidence, low-curvature regions of the dataset can be skipped entirely, which makes the scan affordable.

08 — Supply chain

Dataset and pre-trained weight supply chain

Two attacks that require no access to your infrastructure at all.

Controls for both paths
  • Pin every external dataset and model to a commit revision or hash. Unpinned load_dataset and from_pretrained calls are the enabling condition for the update attack.
  • Scan downloaded weights before fine-tuning. Run Neural Cleanse and activation analysis on the pre-trained model. IBM's ART and Microsoft's Counterfit both do this.
  • Only official, verified publisher accounts. A convincing name is not provenance.
  • Reject non-safetensors weight files outright at the registry and in CI.
  • Post-fine-tune trigger sweep. Apply a library of common trigger patterns to a test set. A clean model degrades roughly uniformly; a backdoored one shows a sharp accuracy spike for one class under one specific pattern.
09 — Attack

Federated learning poisoning

Federated learning removes the defender's ability to inspect the data. That is the entire point of it, and it is also the entire problem.

Where Krum itself fails
  • Too many Byzantine clients. The guarantee requires 2f + 2 < N. At N=10 and f=4 it is already void.
  • Sybils. An attacker controlling many clients makes their own updates the cluster.
  • Direction-aligned attacks. A malicious update crafted to point roughly where honest updates point scores similarly to them.
  • Non-IID data. When honest clients legitimately differ, the honest cluster is diffuse and there is room to hide inside it. Multi-Krum helps partially.
  • Adaptive attackers. Krum's score is computable offline, so it can be added as a constraint to the attacker's own optimisation.

Stronger options: FLTrust and Flame, which keep a small trusted root dataset on the server and accept an update only if it improves performance on that root, and cosine-similarity filtering against the mean update direction.

10 — Defence

Detection in representation space

The strongest family of backdoor defences exploits one fact: the model has to represent the trigger internally, and that representation is unusually consistent.

# spectral signatures, the core of it
R = np.array([model.penultimate(x) for x, y in class_c_data])   # [N_c, d_rep]
R_centered = R - R.mean(axis=0)

U, Sigma, Vt = np.linalg.svd(R_centered, full_matrices=False)
v_1 = Vt[0]                                # max-variance direction
projections = R_centered @ v_1

# backdoored samples align with v_1 → large |projection|
suspects = np.argsort(np.abs(projections))[::-1][:int(eps * len(R))]

# confirm: does removing them collapse the nuclear norm?
drop = (norm(R_centered,'nuc') - norm(np.delete(R_centered,suspects,0),'nuc'))
backdoor_present = drop / norm(R_centered,'nuc') > threshold

Neural Cleanse — reverse-engineering the trigger

A different angle on the same property. If a backdoor targets class t, there must exist a small perturbation that drives almost any input to t. Search for the smallest such perturbation, per class, and compare.

for each candidate target class t:
    minimise  ||m||₁      # sparse mask = small trigger
    such that f( x⊙(1−m) + δ⊙m ) = t   for most x

    m     = mask, per-pixel blend weight in [0,1]  (sigmoid-bounded)
    δ     = the trigger pattern itself
    loss  = CrossEntropy(model(blended), t) + λ·||sigmoid(m)||₁
    # 1000 Adam steps, then record trigger_cost[t] = ||sigmoid(m)||₁
Limits of both techniques

Neural Cleanse assumes a single global trigger and fails on sample-specific triggers, feature-space or style-transfer triggers, and very large triggers where no class is an outlier. Spectral signatures assumes the backdoor affects intermediate representations and misses attacks confined to the final classification layer. Both need access to training data or a representative sample at defence time, and both cost a full forward pass over that data.

11 — Defence

Detection in data space

Cheaper, runs before training, and catches a different failure class. Use both.

Isolation Forest — feature-space outliers

Build random binary trees by picking a random feature and a random split value until every sample is isolated. Anomalies sit in sparse regions, so they isolate in fewer splits.

s(x, n) = 2^( −E[h(x)] / c(n) )

  E[h(x)] = expected isolation depth across trees
  c(n)    = 2·H(n−1) − 2(n−1)/n      # expected BST path length

  s → 1.0   isolated quickly   → anomalous
  s ≈ 0.5   average
  s → 0.0   deep path needed   → normal

# typical scores on a malware feature set
clean samples:     0.1 … 0.8      # hard to isolate
backdoor samples: −0.5 … 0.0      # trigger values are extreme → isolated fast
Four limits worth internalising
  • Adaptive attacks. A trigger constructed to lie on the data manifold produces normal feature statistics and scores ≈0.5. Not detected.
  • Semantic label errors are invisible. A label-flipped transaction with entirely normal features is not a feature-space outlier. Not detected.
  • Curse of dimensionality. Above roughly 10,000 features, distances concentrate and "sparse region" stops meaning anything. Reduce dimensions first.
  • Trigger size versus feature count. Modifying 3 of 65,536 features may not shift isolation depth measurably.

The complement for limit one is an autoencoder trained on clean data: flag samples with high reconstruction error, which catches off-manifold samples that isolation depth misses.

Confident learning — label errors, not feature outliers

# out-of-fold predicted probabilities: each prediction comes from a model
# that never saw that sample in training
pred_probs = cross_val_predict(model, X_train, y_train, cv=5, method='predict_proba')

from cleanlab.filter import find_label_issues
label_issues = find_label_issues(labels=y_train, pred_probs=pred_probs,
                                 return_indices_ranked_by='self_confidence')

# self_confidence(x_i) = P(class = given_label | x_i)
# consistently low across folds → the model disagrees with the label → likely error
# class threshold c_j = mean P(class=j | x) over samples whose given label is j
The diagnostic that finds a compromised data source

Do not just count label errors. Break the error rate down by source. Natural label noise is 0.1–0.3% and distributes roughly evenly. A single vendor feed running at 3× the rate of every other source is the finding.

for source in data_sources:
    errs = cleanlab_issues[cleanlab_issues.source == source]
    print(f"{source}: {len(errs)/len(source_data[source]):.1%}")
12 — Prevention

DP-SGD: bounding what one sample can do

Differential privacy is usually sold as a privacy control. Its poisoning resistance is a direct consequence of the same mechanism, and it is the only defence here that works without knowing what the attack looks like.

A mechanism M is (ε, δ)-differentially private if, for datasets D and D′
differing in one sample and any output set S:

        P[M(D) ∈ S]  ≤  e^ε · P[M(D′) ∈ S] + δ

DP-SGD adds exactly two operations to ordinary SGD:

1. per-sample gradient clipping     g_i ← g_i · min(1, C / ‖g_i‖)
   # bounds sensitivity: the most any single sample can contribute

2. calibrated Gaussian noise        g̃ = Σ g_i + N(0, σ²C²I)
   # masks the bounded contribution
ε < 1Strong privacy, academic benchmark. Typically 3–5% accuracy loss.
ε = 1–8Moderate. The industry working range. 1–3% accuracy loss.
ε > 10Weak guarantee, near-full utility, some residual poisoning resistance.
δProbability the guarantee fails. Set δ = 1/N². At N=500,000 that is ≈4×10⁻¹².
σDerived from (ε, δ) via the moments accountant. Roughly √(2·ln(1.25/δ)) / ε; at ε=8, δ=10⁻¹² gives σ≈0.7.
CSet to the median gradient norm on clean data. Too small hurts utility, too large blunts the noise.
State the guarantee honestly

DP gives a probabilistic bound, not a barrier. It raises the floor on how much poisoning is required to succeed. A sufficiently large injection, or a high ε, still gets through. Do not write "we use DP-SGD" in a control document and treat poisoning as mitigated; write the ε you chose, the σ it implies, and the poison count that would overcome it.

13 — Posture

Attack surface and defence in depth

STRIP — the runtime detector

The one defence that runs per request. Superimpose random clean samples onto the input several times and measure how much the prediction moves. A clean input under perturbation produces varied outputs; a trigger overrides the perturbation and pins the output.

for _ in range(20):
    alpha = uniform(0.3, 0.7)
    perturbed = alpha * x + (1 - alpha) * random_clean_sample()
    outputs.append(softmax(model(perturbed)))

entropy = −Σ mean(outputs) · log(mean(outputs))

entropy ≈ 1.5   varied predictions      → clean input
entropy ≈ 0.1   pinned predictions      → trigger present

# cost: 20× inference per protected request. Reserve for high-stakes decisions.

Incident response: compromised annotation vendor

  • HoursContain Freeze ingestion from the suspect service. Query the registry manifests for every model whose dataset_sources includes it — that is the blast radius. Roll production back to the last version predating the suspect data. Snapshot the labelled dataset immutably and preserve annotation logs before anything is touched.
  • DaysAnalyse Cross-source label consistency against internal annotators and against the pre-poison model's own predictions. Run cleanlab using a model trained on a separately trusted dataset. Run activation clustering and Neural Cleanse on the deployed poisoned model to establish whether a backdoor was actually learned or only degradation occurred. Break error rates down by individual annotator ID — concentration in one to three accounts means compromised accounts, distribution across all means service-level or post-processing compromise.
  • WeeksRemediate Re-label everything that failed consistency, was cleanlab-flagged, or came from an implicated annotator. Retrain from scratch, do not fine-tune — fine-tuning can leave backdoor pathways intact in the early layers. Redeploy with Neural Cleanse and activation clustering as permanent pre-registry gates, and annotation cross-checking as a permanent ingestion control. Update the vendor contract to require annotator identity verification and label-change audit logging.

Drills

  1. Plant a backdoor. Take CIFAR-10, add a 3×3 white patch to 0.5% of samples, relabel them to one class, and train. Verify clean accuracy is unchanged and attack success rate is above 95%.
  2. Then find it. Run activation clustering on your own poisoned model. Confirm the poisoned cluster appears and measure how low you can push the poison rate before it stops appearing.
  3. Reverse the trigger. Implement Neural Cleanse and check that the recovered mask resembles the patch you planted.
  4. Break the defence. Build a clean-label version with no label flip and confirm cleanlab finds nothing.
  5. Measure the DP trade-off. Train the same model with DP-SGD at ε ∈ {1, 8, ∞}. Record the accuracy cost and whether the backdoor still installs at each setting.
  6. Audit a real pipeline. Pick a model in your organisation and answer: which dataset versions produced it, are external datasets revision-pinned, is a backdoor scan a registry gate, and could you enumerate the blast radius of a compromised source in under an hour?
Model collapse, the poisoning nobody is committing

Generative models trained on their own outputs lose distribution tails each generation. With P_data = α·P_real + (1−α)·P_model, the objective rewards matching a lower-entropy distribution, and entropy decreases monotonically across generations. It is a poisoning failure mode with no attacker, no trigger and no label flip. It also has a deliberate version: flooding public corpora with generated text carrying a specific slant, or generated code carrying a subtle vulnerability pattern, so that models fine-tuned on scraped data inherit it. The defences are provenance filtering, generated-content detection, output diversity monitoring, and watermarking.

How to use this. Sections 1 to 4 establish the system and where the trust boundaries sit. Sections 5 to 9 are the attacks. Sections 10 to 12 are the defences, ordered by where they run: representation space after training, data space before training, and the training algorithm itself. Sections 13 and 14 are posture and operations.

The one idea to keep. Every metric on your dashboard is computed on data that, by construction, does not contain the attack. A backdoor scan is not an evaluation metric and cannot be derived from one. It has to be a separate, explicit gate that somebody owns.
