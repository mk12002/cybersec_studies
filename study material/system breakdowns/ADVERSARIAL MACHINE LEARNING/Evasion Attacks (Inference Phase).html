Adversarial Machine Learning 14 Sections

Inference-Time Evasion Attacks

A trained model is a differentiable function from inputs to outputs. Give an attacker the gradient of that function and the decision boundary becomes a map. This is how evasion works, and why almost every published defence has failed.

01 — Narrative

Two bypasses, end to end

Two production systems carry this document. A static malware classifier at an email gateway, and a CNN face-recognition reader on a door. They fail the same way for the same reason.

System A — malware evasion

  • normalThe intended path Attachment arrives. Gateway extracts the binary, submits it to the classifier. The API pulls 2,381 static features: PE header fields, import-table hash, per-section entropy, byte n-gram histograms. Normalise with the training set's μ and σ, run a LightGBM plus feed-forward ensemble, return a verdict in about 76 ms.
  • attackSemantics-preserving modification The attacker appends 200 KB of benign DLL code and edits the overlay section. Section entropy drops from 7.8 to 5.2 as the high-entropy packed region is diluted. Rare byte n-grams drop by an order of magnitude. The import hash is untouched because changing it would break execution. Verdict flips from 0.99 malicious to 0.91 benign, and the payload at offset 0x1000 is bit-for-bit unchanged.

System B — biometric bypass

  • normalThe intended path Camera captures 1080p. MTCNN or RetinaFace detects the face and five landmarks. An affine transform aligns on eye positions and crops to 224×224. ResNet-50 with an ArcFace-trained backbone produces a 512-dimensional unit-normalised embedding. Cosine similarity against the enrolled template; above τ = 0.85, the door opens.
  • attackA printed photograph The attacker perturbs a face image by at most 8/255 per channel, prints it, and holds it up. Cosine similarity to the victim's template goes from 0.30 to 0.92. The perturbation is roughly two intensity units out of 255 and is invisible to a human standing next to the reader.
Why alignment does not save you

People assume the crop-and-align step destroys adversarial perturbations. It does not. The alignment algorithms are open source, so the attacker knows exactly which pixels survive, and the transform is differentiable, so it can simply be included in the attack's optimisation loop. The attacker optimises the camera-facing image such that after alignment the desired perturbation lands on the CNN's input. Any deterministic differentiable preprocessing step is part of the model as far as the attack is concerned.

02 — Pipeline

Preprocessing and trust boundaries

Two secrets people forget to protect

The normalisation statistics. The μ and σ vectors are derived from the training distribution. An attacker holding them knows precisely what "benign" looks like in feature space. Keep them in the model registry, never in an API response or a client-side bundle.

The model weights. Stolen weights turn every black-box attack into a white-box attack, which is roughly a thousand-fold reduction in attacker effort. Encrypt artifacts at rest with a KMS key restricted to the inference service role, and keep biometric templates in a separate bucket under a separate key with a separate IAM policy.

Dimensionality is the attacker's budget

2,381malware features derived from ~500 KB of attacker-controlled bytes
150,528image input dimensions, 224×224×3
8/255typical L∞ budget, about 0.03 in normalised space
512embedding dimensions the decision actually depends on

Even a tiny per-dimension budget spans an astronomically large set when there are 150,528 dimensions. The L∞ ball around any input contains vastly more points than were ever sampled during training, and almost all of them look identical to a human.

03 — Architecture

Architecture and differentiability

The choice between trees and networks changes which attacks apply. It does not change whether the system is attackable.

Branch 1 · LightGBM

500 trees, max depth 8. Each tree is a piecewise-constant function; the ensemble output is σ(Σ treeᵢ(x)).

Not differentiable. Within a leaf the output does not change as x changes, so ∂L/∂x = 0 almost everywhere and is undefined at leaf boundaries. FGSM does not apply.

Still not robust. Genetic algorithms, boundary attacks and decision-based attacks need no gradient at all.

Branch 2 · Feed-forward network 
2381 → 512 → 256 → 128 → 2
Linear → BatchNorm → ReLU → Dropout(0.3)

Differentiable everywhere except the ReLU kink, where a subgradient is used. Every operation admits backpropagation to the input, which is exactly what FGSM and PGD need.

# the ensemble that combines them
p_final = 0.4 × p_tree + 0.6 × p_nn
verdict = "malicious" if p_final > 0.5 else "benign"

# the reason for the ensemble is coverage across feature subsets,
# not robustness. A 60% weight on a differentiable branch means
# gradient attacks still move p_final substantially.

The ArcFace embedding, and why the threshold is geometry

ResNet-50 produces a 512-dimensional feature vector, unit-normalised so that it lies on the hypersphere S⁵¹¹. ArcFace's training head adds an angular margin, pushing classes further apart on that sphere. At inference the head is discarded and identity matching is a dot product.

05 — Attack

FGSM — one step, exactly optimal

Goodfellow et al., 2015. The whole attack is one line, and the sign function in it is not a heuristic.

x_adv = x + ε · sign( ∂L(f_θ(x), y) / ∂x )

# why sign, not the raw gradient?
# the constraint is an L∞ ball: every dimension may move at most ε.
# maximise  δ·g  subject to  ‖δ‖∞ ≤ ε
# the exact solution is  δ = ε·sign(g).  Not an approximation.

# raw gradient instead → large-magnitude dimensions blow the budget while
# small-magnitude dimensions leave theirs unused. Strictly worse.
# L2-normalised gradient instead → solves the L2-constrained problem,
# which is the C&W / DeepFool family.
# targeted white-box FGSM against the face model
def fgsm_attack(model, x, target_embedding, epsilon=8/255):
    x_adv = x.clone().requires_grad_(True)
    embedding = model(x_adv)                       # (512,), unit-normalised
    loss = -F.cosine_similarity(embedding.unsqueeze(0),
                                target_embedding.unsqueeze(0))
    model.zero_grad(); loss.backward()
    x_adv = x + epsilon * x_adv.grad.sign()
    return torch.clamp(x_adv, 0, 1).detach()       # stay a valid image
Where FGSM falls short
  • One step only. It linearises the loss around x. Where the boundary is curved, the straight-line step misses.
  • Fixed step size. Large ε overshoots and can reduce success.
  • Untargeted by default. It increases the loss for the true class. Forcing a specific wrong class needs the gradient of the target class's loss instead.
06 — Attack

PGD and C&W

Carlini & Wagner — minimise the perturbation instead of bounding it

PGD fixes ε and maximises loss. C&W inverts the problem: find the smallest L2 perturbation that achieves misclassification. That inversion is why it broke essentially every defence published before 2017.

minimise  ‖δ‖₂²  +  c · loss(x + δ, t)

loss(x, t) = max( max_{i≠t}(logit_i) − logit_t , −κ )
#   zero once the target logit leads by margin κ; otherwise it measures
#   exactly how far from misclassification we still are

# box constraint handled by change of variables, not projection:
δ_i = (tanh(w_i) + 1)/2 − x_i        # w unconstrained → Adam works well
# plus binary search over c, ~1000 iterations
The lesson from 2017 that still holds

Ten of the strongest published defences failed completely against C&W, having reported success against FGSM and PGD alone. C&W finds smaller perturbations, which input preprocessing cannot destroy, and it uses the full gradient magnitude rather than only its sign, which makes it effective on smooth models. A defence evaluated only against FGSM has not been evaluated.

08 — Attack

Black-box attacks

Most production systems return a hard label and nothing else. Defenders read that as "no gradient information, therefore no attack". It is not true, and the belief is load-bearing in a lot of deployed systems.

Detect the query pattern, since you cannot hide the boundary 
# black-box attacks are query-hungry; normal users are not
hour_key = f"queries:{api_key}:{now:%Y%m%dT%H}"
redis.sadd(hour_key, sha256(input));  redis.expire(hour_key, 7200)
n = redis.scard(hour_key)

if n > 1000:   log.warning("possible model extraction")
if n > 5000:   raise RateLimitExceeded()

# the discriminating signal is UNIQUE inputs per key per hour,
# not request volume. A batch scanner sends many requests but
# few near-duplicates; a boundary attack sends thousands of
# minutely-different variants of one input.
09 — Foundation

Why models fail at all

This is not an implementation bug. No amount of careful engineering removes it, which is why the defences in the next three sections all cost something real.

Manifold hypothesisNatural images and files occupy a low-dimensional manifold inside a very high-dimensional space. Training only ever sampled that manifold. Off it, the model is extrapolating with no constraint, and adversarial examples live off it.
Excessive linearityGoodfellow's original argument. A perturbation of ε=8/255 across 150,528 dimensions produces a dot product with the weights on the order of ε·d·w̄ ≈ 452. The model is exquisitely sensitive to the sum of many individually invisible changes.
High-dimensional geometryThe ε-ball around any input contains exponentially many points, essentially none of which were sampled. Without explicit training to be constant inside that shell, the model's behaviour there is arbitrary.

All three point at the same conclusion. The model was never asked to be constant over a neighbourhood, only to be correct on a finite sample. Adversarial robustness is a different training objective, not a better-tuned version of the same one.

10 — Defence

Adversarial training

The most effective defence and the most expensive. It changes the objective from "be correct on the data" to "be correct on the worst point near the data".

# standard training
min_θ  E_(x,y)~D [ L(f_θ(x), y) ]

# adversarial training — a saddle-point problem (Madry et al., 2018)
min_θ  E_(x,y)~D [ max_{‖δ‖∞ ≤ ε}  L(f_θ(x + δ), y) ]
       └── outer: update weights          └── inner: find the worst δ for THIS x
                                              with the CURRENT weights, via PGD
The malware-specific problem: feature space is not input space

For images, every point in input space is a valid image, so a feature-space perturbation is trivially realisable. For malware it is not. The features are a many-to-one function of the binary, and most feature vectors correspond to no valid PE file at all. Adversarially training on arbitrary feature perturbations teaches robustness to inputs the attacker cannot construct, which buys you nothing.

Valid, semantics-preserving
  • Append data to the overlay
  • Insert NOP sleds into code caves
  • Add unused API imports
  • Edit header metadata such as the timestamp
  • Add new sections with benign content
Fictional — do not train on these
  • "Set section entropy to 3.5" without changing bytes
  • "Set import count to 0" without removing imports
  • Any direct assignment to a derived feature

Correct adversarial training for malware perturbs the binary, re-extracts features, and trains on those. That means solving the inverse feature-mapping problem, which is why malware robustness research lags image research by years.

11 — Defence

Certified robustness

Empirical robustness says "this attack failed". Certified robustness says "no attack within radius R can succeed". Only one of those is a guarantee.

# the smoothed classifier (Cohen et al., 2019)
g(x) = argmax_c  P_{ε~N(0,σ²I)} [ f(x + ε) = c ]

# the theorem
if  p_A = P[f(x+ε) = A] > 0.5   then for ALL δ with ‖δ‖₂ ≤ R:
        g(x + δ) = A
    where   R = σ · Φ⁻¹(p_A)

# in practice, estimate p_A by Monte Carlo
1. sample n = 10,000 noise vectors from N(0, σ²I)
2. count how often f(x + εᵢ) = A
3. take a Clopper–Pearson LOWER bound p_A_lower  # must be a bound, not the estimate
4. certified radius R = σ · Φ⁻¹(p_A_lower)
5. if p_A ≤ 0.5 → abstain
Four limits, all of them load-bearing
  • L2 only. Gaussian noise is optimal for L2 by Neyman–Pearson. There is no comparably strong L∞ result, and L∞ is the more common threat model.
  • Cost. 10,000 forward passes per prediction. A face reader doing 500 verifications per second would need five million forward passes per second.
  • The σ dial cuts both ways. Larger σ certifies a bigger radius and destroys clean accuracy. At σ=0.25 you get R≈1 with ~70% accuracy; at σ=1.0, R≈4 with ~50%.
  • Abstention is a denial-of-service surface. An attacker who crafts inputs where p_A ≤ 0.5 forces the system to abstain, which for a door reader means nobody gets in.
12 — Defence

Sanitization and its limits

Feature squeezing

Adversarial perturbations tend to live in high-frequency, low-amplitude components. Remove those components and compare the prediction before and after. The signal is inconsistency, not the squeezed prediction itself.

x_squeezed = one of:  Gaussian blur σ=1.5 · 3×3 median filter · bit-depth → 4 bits

if | confidence(f(x)) − confidence(f(x_squeezed)) | > τ:
        REJECT — likely adversarial
else:   return f(x)

# natural inputs are stable under squeezing; a precisely optimised
# perturbation often is not.

The malware analogue: semantics-preserving normalization

The same idea, expressed in the domain's own operations. Each of these destroys a specific known feature-manipulation technique without changing what the binary does when executed.

Strip the overlayBytes after the last section. Defeats the padding and append attacks directly.
Zero the PE timestampRemoves timestamp-derived features from the attack surface.
Sort the import tableDestroys import-order features.
Drop unused resourcesRemoves resource-section entropy manipulation.
Re-pack sections with a standard packerNormalises section entropy, the single most-gamed feature.
The detectorIf the verdict before normalisation differs from the verdict after, the binary was shaped to exploit feature extraction. That disagreement is the finding.
Adaptive attacks defeat every non-adaptive defence

Feature squeezing, blurring, JPEG re-encoding and binary normalisation all fall to an attacker who includes the defence in their optimisation loop. Optimise for an input that is still adversarial after blurring, and blurring stops helping. This is the central finding of Tramèr et al., 2020: a defence is only valid if it survives an attacker who knows it is there. Any evaluation against an attacker who does not know about the defence is measuring nothing.

13 — Defence

Gradient masking, and how to catch it

The most common way a defence paper is wrong. The gradient is obscured, the boundary is not moved, and the model is exactly as breakable as before.

Three mechanisms produce it: shattered gradients from non-differentiable operations such as argmax or floor; exploding or vanishing gradients from numerically unstable architectures; and defensive distillation, which trains on soft teacher labels to produce smaller, smoother gradients. All three make white-box gradient attacks harder. None of them moves the decision boundary away from the data, which is what robustness actually requires.

The asymmetry that breaks capacity planning

The attacker pays once, offline, to craft an adversarial example: roughly ten minutes of GPU time. Submitting it costs nothing and looks identical to normal traffic at the infrastructure layer — same size, same latency, same memory. The defender pays per query for whatever expensive defence is deployed. One crafted example replayed a thousand times costs the attacker nothing and the defender a thousand smoothing evaluations.

Mitigations: rate-limit per API key; cache adversarial-detection verdicts by input hash so replays are free; push expensive defences to the async path where the latency budget is generous; and reserve smoothing for the confidence band where it changes decisions.

Do not alert on individual adversarial flags, single slow requests, PSI below 0.1, or low-confidence predictions. Those are the model working as designed, and paging on them produces the analyst fatigue that causes the real detection to be ignored.

Recovering precision without giving up the defence

Unconditional defences raise the false-positive rate; conditional ones do not. Legitimate software is often packed, compressed or obfuscated for IP protection, which looks exactly like the adversarial signature. Rather than applying strip-and-reanalyse to everything:

  • Two-phase classification. If the first pass is above 0.99 benign, deliver. Only the ambiguous band gets the expensive normalisation, which is precisely the band an attacker targets.
  • Inspect the overlay before stripping it. Executable code in an overlay on a file that was high-confidence malicious pre-strip is a far stronger signal than the verdict flip alone.
  • Reputation and code signing as priors. A valid Authenticode signature from a trusted publisher, or a known hash, removes the need for reanalysis entirely.
  • Sender history. A domain that has delivered clean files for years, sending a file that matches its historical profile apart from an overlay, is probably shipping an update.

Drills

  1. Implement FGSM from scratch against a small CIFAR model. Confirm that sign() beats the raw gradient at equal L∞ budget, which is the claim in section 5.
  2. Sweep ε from 0 to 0.3 and plot accuracy. Learn what a smooth degradation curve looks like so you can recognise a cliff.
  3. Adversarially train the same model with PGD-10 and re-plot. Measure both the clean accuracy you lost and the robust accuracy you gained.
  4. Break your own defence. Add median-filter squeezing, confirm it helps, then write an adaptive attack that includes the filter in its forward pass and watch the gain disappear.
  5. Run a decision-based attack using only hard labels. Count the queries needed. Then implement the unique-input-per-key detector and check whether it would have fired.
  6. Do the malware version properly. Write a semantics-preserving binary transform, apply it, re-extract features, and confirm the verdict flips. Then implement overlay stripping and confirm the verdict-disagreement detector catches it.

The one idea to keep. A defence is only worth what it is worth against an attacker who knows it is there. Every result in this document that later turned out to be wrong was wrong for that reason, and the correction is always the same: evaluate with a decision-based attack, a transfer attack, and an adaptive attack that includes your defence in its loop.
